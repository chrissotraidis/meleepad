# MeleePad v0.1.0 Preview 4

Preview 4 is build 18. It adds recommended USA v1.02 support alongside v1.00,
floating touch controls, clearer version selection and Online Play, reduced
normal CPU-loop overhead, and lightweight gameplay frame-time summaries.
macOS branding and explicit keyboard mappings are corrected.

Each revision keeps its own game data and saves. Existing imports remain in
place. The menu identifies the selected version, and online peers must use the
same app build, revision, modules, assets and compatible gameplay settings.

The physical build-17 comparison reduced the normal execution loop's sampled
self time by 41.8%, with total CPU-thread samples 2.38% lower in that interval.
This is a modest targeted optimization, not a 42% FPS gain. Owner testing reports
improvement, but heavy iPhone scenes still slow down under thermal pressure.
Build 18 adds logging to help investigate those remaining cases.

Gameplay logs now report frame-interval count, average, p95 upper bound, maximum,
counts above 20 ms / 33.33 ms / 50 ms, and audio underruns since the previous
summary. The p95 uses 1 ms buckets (the observed maximum for the overflow bucket).
These are host frame intervals, not GPU execution times or exact missed-vblank
counts. Existing pause invalidation excludes the first resumed interval. The
recorder reuses existing frame timestamps, keeps a fixed-size accumulator and
writes through the existing ten-second log; per-dispatch profiling stays off.
Logs remain on-device unless the user shares them through Report a Problem.

Private Room and Direct IP remain experimental. There is no production public
game browser, relay fallback, ranked matchmaking or Slippi rollback. Completed
physical iPhone-to-iPad Internet-match acceptance remains open.

## Download and local builds

`MeleePad-v0.1.0-preview.4-module-free-unsigned.ipa` is an unsigned iOS/iPadOS
16+ ARM64 app shell, **not playable as downloaded**. It excludes game images,
extracted assets, saves, provisioning profiles and both generated game modules.
Importing an ISO into the public shell alone cannot make it playable.

Build and sign a playable app locally using your own supported image and Apple
development identity. The locally installed owner builds include the existing
private modules; those modules and the device game data are not release assets.
